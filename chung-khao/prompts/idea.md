## Procedure: diverge -> filter -> score -> pick -> upgrade -> red-team

1. **Parse:** quote the brief's deliverable, audience, rubric, submission requirements and hard rules. Mark missing facts `UNKNOWN`; request verification or state an assumption. Do not silently upgrade an inferred theme to an official one.
2. **Diverge:** create at least **five materially distinct candidates** (different audience/task/signature mechanism, not five visual skins). Include the team's rough sketch as one candidate unless it breaks a hard rule. One line each: hook, user action, 10-second reveal, key dependency, gateway-free fallback.
3. **Filter:** apply the hard gates above; reject with a one-line reason. For data ideas, identify reachable primary sources and collection/validation plan before calling them factual.
4. **Score:** use the current rubric when available; otherwise use the weighted table above. Show the top three candidates' 0-3 scores, weighted totals, and one concrete uncertainty each. Identify the **winner**, not a menu of equally recommended concepts.
5. **Upgrade:** preserve a complete MVP; add a Target layer only if it improves the signature user task, and a Stretch layer only if time, gateway responsiveness, and spend allow. Assign parallel work to two producers; Coordinator/QA owns sources, cost/time checks, Vietnamese QA and demo verification. If only two teammates are active, one producer also owns QA. 6. **Red-team:** simulate a judge's first 10 seconds and one actual use; challenge originality, source trail, diacritics, formats, accessibility, mobile/desktop or print legibility, consistent style, gateway outage, and late export. Specify an offline/manual fallback and a point to stop upgrades. [HYPOTHESIS]

## Required final-idea response template

Use these headings in this order. Keep the response skimmable; tag factual claims and predictions. No source -> no real-world factual claim in the product.

1. **Brief and assumptions:** confirmed theme/rubric/deliverable, unknowns, source tags; note whether search was available, used, and what it verified.
2. **Divergence and selection:** five candidate hooks with dependencies/fallbacks; hard-gate rejects; top-three scoring table (or official rubric comparison); 2-3 rejected alternatives with reasons.
3. **Final idea:** one-line concept and hook; intended audience and its one primary action; why this could win (label prediction `[HYPOTHESIS]`); intended judge reaction (prediction); visible signature wow moment in the first 10 seconds.
4. **Scope:** MVP (finished, testable, submitted in time), Target (only after MVP), Stretch (optional), stop-upgrading trigger; what a judge can actually try or play.
5. **Risks and fallback:** gateway delay/429, tool unavailability, unverified fact, quality, time and spend; for each give mitigation, owner and gateway-independent alternative.
6. **Authenticity and truthfulness:** local specificity, source -> collection -> validation -> output chain, attributed claims, synthetic-media labelling where needed, sensitive-content review and Vietnamese format/accent checks.
7. **Vietnamese content notes:** exact audience voice, sample Vietnamese title/hook or dialogue (short), typography/overlay plan, pronunciation/diacritic review. Keep the operational prose in English.
8. **Tools and rough cost:** exact tool/model IDs, protocol/permission check, estimated calls/tokens/clips with USD arithmetic and uncertainty, live remaining-budget check. Say `UNKNOWN` instead of inventing Suno pricing or unavailable model access.
9. **Planning handoff:** two parallel producer workstreams, Coordinator/QA checks (or two-person merge), asset/source dependencies, demo acceptance criteria, offline fallback deliverable, and submission-format questions for the next stage. Do **not** write the workflow yet.
